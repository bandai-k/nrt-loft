## 1. NRT LOFT とは

成田にある拠点の名前であり、そこで行われている活動の名前。
AIを使って「自分の困りごとを解決する小さな仕組み」をつくり、その過程を記事とYouTubeで発信するメディア。

- 運営: Nebulab合同会社
- 発信者: Koki（エンジニア、成田、小学生と中学生の子どもがいる）
- サイト: https://www.nrt-loft.jp/
- リポジトリ: https://github.com/bandai-k/nrt-loft
- デプロイ: Vercel（nrt-loft.vercel.app）

拠点はリノベーション途中。未完成のまま活動拠点として使用中。
完成後にレンタルスペースとして機能させることを検討中（前面には出さない。予約機能はサブページで将来的に）。

## 2. 立ち位置（変更しない前提）

- 読者は非エンジニアの生活者
- 発信者はエンジニアだが、それを隠さない
- 役割は「エンジニアが一般の人にAIでのものづくりを翻訳する」
- 「プログラミングを学ぼう」でも「アプリ開発者になろう」でもない
- 「AIで副業」「AIで稼ぐ」は主軸にしない
- 伝えたいのは「欲しいものがなければ、自分で作ってしまう」という新しいAIの使い方そのもの

### 作るものの呼び方

「アプリ開発」とは言わない。「小さな仕組み」「自分専用ツール」と表現する。
実装方式にこだわらない（Webツール、ローカルツール、自動化スクリプト、必要ならiOSアプリ）。

### 最重要の思想

公開サービスを作ることを最初の目的にしない。
まず「自分ひとりが使えればいい」からスタートする。需要がありそうなら、後から公開やサービス化を考える。

### 差別化は3点だけ

1. 成田の自分の家という具体性
2. 失敗を出すこと
3. 家族に渡して断られる過程

**題材では差別化しない。** 生活系のAI活用事例（note、リベシティ、Qiita）は既に多数存在する。調査で確認済み。

### 隠れた軸が2つ

- **紙で出す** — 家族に使われた自作ツールは全部が紙で出るものだった。他のAI系メディアは家庭でプリンターを使わないので書けない
- **学年差** — 小学生と中学生で同じ仕組みが通じるか。ひとりっ子の家庭では書けない

## 3. カテゴリ

| カテゴリ | 内容 |
|---|---|
| BUILD | 実際に何かを作る記録。サイトの中心コンテンツ |
| LEARN | 作って分かったこと、失敗、AIとの付き合い方 |
| TOOLKIT | Claude Code、Codex、プロンプト、開発環境、AI料金プラン |
| JOURNEY | NRT LOFT自身の活動記録、数字、試行錯誤、裏側 |

BUILDを中心に置き、他の3カテゴリが補助する構造。

判定は記事の入口で決める。使った道具では決めない。
**記事の1行目が困りごとから始まるならBUILD、道具から始まるならTOOLKIT。**

DIY（リノベーション、キャンプ用品、3Dプリンター、レーザーカッター）は独立カテゴリを作らない。
拠点の話はJOURNEY。それ以外は上記の判定に従う。DIYは記事の中の比喩として使う（シリーズの通し軸）。

技術から入らない。

1. 日常の困りごと

## 7. 実装で必要になること

### 記事の置き場所

44本の記事を出す前提の構成が必要。判断が必要な点：

- MDX / Markdown ファイルベースか、CMS（Notion API等）か
- カテゴリ別の一覧ページ（BUILD / LEARN / TOOLKIT / JOURNEY）
- 記事間の内部リンク（シリーズとして相互参照が多い）
- 公開順の管理

**Notion に企画DBがあるので、Notion API で記事を引く選択肢もある。**
ただし記事本文はリライト後に確定するので、リポジトリ内のファイルで持つほうが素直かもしれない。ここは未決。

### SEOの制約

「NRT LOFT」で検索してもブランド名では見つけてもらえない（LOFTもNRTも一般語すぎて、雑貨店・空港・ライブハウスに埋もれる）。
そのため、記事タイトルは具体的な困りごとのキーワードで検索から入ってきてもらう設計にする必要がある。

各記事に「狙う検索キーワード」が Notion に入っている。

### 将来的に必要になるもの

- レンタルスペースの予約機能（サブページ。リノベーション完成後）
- Googleビジネスプロフィール連携（成田のローカル検索）

**成田を出す方針は確定している。** NRTを冠しているので伏せる意味がない。

## 8. 触ってはいけない領域（記事の話）

法人メディアが数日単位で更新しており、網羅性と更新頻度で勝てない。**見出しにこれらを置かない。**

- 「Claude Codeとは」「完全入門」「使い方」
- 料金プランの網羅的な比較表
- Cowork / Codex / Claude Code の機能比較表
- 「用途に応じて選びましょう」で終わる結論

**書いてよい場合**: 自分の実額・実体験としてなら書ける。冒頭で「◯年◯月時点の自分の環境の話。一般論ではない」と宣言し、そのうえで断言する。

### 調査で分かった競合状況（2026年9月時点）

- プリント管理系: 既存アプリ（プリゼロ、ポスリー、まなびの手帳）とベネッセ・VERYが上位
- 料金系: 法人メディア（Uravation、SHIFT AI、Jicoo、Fyve等）が占拠
- 入門系: 33万再生の動画がある（パソコン博士TAIKI）
- 生活系AI活用: note / リベシティ / Qiita に多数。プリント管理アプリを Claude Code で自作した Qiita 記事が既に存在する

### 前提が古くなっている点（重要）

当初「非エンジニアには黒い画面が壁」という前提で企画したが、調査の結果それが崩れていた。

- Claude Cowork が非エンジニア向けに提供されている（$20 Pro プラン以上に含まれ、追加料金なし。ターミナル不要）
- Claude Code もデスクトップ版でチャットUIから使える
- Codex も $20 で使える

**記事で「黒い画面が怖い非エンジニア」という導入を使うと古く見える。**
T2（20ドル/100ドルの記事）は3択（$20 Claude Code / $20 Codex / $100 Claude Code）にする必要がある。

## 12. Web と YouTube と SNS の関係

Web記事を原稿として作る → 記事をベースにYouTube撮影 → 動画から詳細記事へ誘導。
**別々にコンテンツを作らない。**

正確な順序：

```
素材を撮る（作る前） → 作る（このあいだXで断片を投げる） → 記事 → YouTube → Instagram
```

**素材の撮影が記事より先に来る。** 記事から始めるとBefore素材が失われる。

| 段階 | 役割 |
|---|---|
| Web | 詳しい手順、プロンプト、補足、使用ツール、コード |
| YouTube | ストーリー、制作過程、実際に動くところ、考え方、Before/After |
| Instagram | 成果物の写真（YouTubeから切り出す） |
| X | 制作中の断片、依頼文の全文公開、失敗談 |

第1期（0〜3ヶ月）は YouTube と X だけ。Instagram は第2期。
運用ペース: 記事 月4〜5本 / 動画 月2〜3本 / X 週3〜5。

**3ヶ月は数字を見ない。** 新規チャンネルは構造上伸びない期間。本数を出すことだけを目標にする。

## 13. Claude Code 側で最初にやってほしいこと

1. `src/` の中を確認し、記事一覧を持つ構成になっているか判定
2. 上記6章の「確認が必要な点」を解消（設定ファイルの重複、ルート直下のjsx、renewal ディレクトリ）
3. Skill を `.claude/skills/nrt-loft-editor/` に配置
4. 記事の置き方を決める（MDX / Markdown / Notion API）
5. 決まったら、B5（旅行のしおり）を1本目のリライト対象として Notion から取得

**記事のリライトは1本ずつ。** 44本を一括で処理しない。1本ごとに Skill で添削し、素材と※を埋める工程が入る。
